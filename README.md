# CtrlZ — 活动历史与因果回退（Minecraft 26.1.2 / Fabric）

记录玩家的**活动（Activity）**以及活动造成的**连锁反应（Consequence）**，并通过游戏内 GUI 查看历史、按键回退单个活动，且回退时连带撤销它造成的连锁反应。

- Minecraft **26.1.2**
- Fabric Loader **0.19.3**
- Fabric API **0.155.2+26.1.2**
- Java **25**（26.x 起 MC 官方 jar 不再混淆，工程内不写 `mappings`）

> 26.x 的 Minecraft jar 已经是官方名称（`net.minecraft.*`，其中 `ResourceLocation` 已更名为 `net.minecraft.resources.Identifier`）。因此本工程没有 Yarn/Intermediary 配置，直接用官方名编译。

## 1. 功能

| 能力 | 说明 |
|---|---|
| 活动记录 | 走路/疾跑/潜行/飞行/游泳（连续移动合并为一个活动）、跳跃、攻击与暴击、挖掘、放置、使用物品、打开容器、背包与容器内移动物品、合成、丢弃、拾取 |
| 活动合并 | 连续动作视为一个活动：走路过程中转向仍是同一个 `MOVE` 活动；连续挖掘/连续点击容器在合并窗口内合并 |
| 轨迹压缩 | 逐 tick 采样 → 关键帧（RDP 折线简化 + 状态变化点保留 + 固定点 1/128 格量化 + 增量变长编码）。直走 600 tick ≈ 2 个关键帧 |
| 因果追踪 | 每个连锁反应都带 `activityId` + 父连锁反应 + 因果类型（`DIRECT` / `INDIRECT` / `DELAYED` / `UNATTRIBUTED`）+ 发生刻 |
| 回退 | 逆序回退、先做冲突检测、失败整体回滚（事务一致性）、无法安全回退的活动标记 `NOT_ROLLBACKABLE` 并给出原因 |
| GUI 历史 | `G` 打开；每行一个活动（时间/类型/坐标/距离/连锁反应数/状态），可翻页、查看详情、单条回退 |
| GUI 配置 | `K` 打开；开关页 + 数值页，保存后写入服务端配置（需要权限等级 3） |
| 持久化 | 追加式分片日志 + CRC32C 校验 + 崩溃截断修复 + 自动保存 + 容量/条数限制 + 分片清理 |
| 可选后端 | 检测到 [MineTracer](https://modrinth.com/mod/mine-tracer)（MIT，服务端 mod）时，用它的方块/容器审计表做**交叉校验**：本地快照与外部审计不一致时拒绝回退，避免"自信地恢复错误状态" |

## 2. 安装

1. 服务端与客户端都放入 `ctrlz-1.0.0.jar`（单人游戏即客户端内置服务端，同一套逻辑）。
2. 安装 Fabric API `0.155.2+26.1.2`。
3. 可选：服务端放入 `minetracer-fabric-26.1.2-*.jar` 以启用交叉校验（`ctrlz.config.useMineTracerAudit` 默认开启，未安装时自动降级为纯内置校验）。

数据目录：`<世界存档>/ctrlz/history/`（`activities/` 与 `consequences/` 分离存储，通过活动 ID 关联）。
配置文件：`<世界存档>/ctrlz/config/ctrlz.json`（首次启动自动生成）。

## 3. 操作

| 按键 | 作用 |
|---|---|
| `G` | 打开活动历史 |
| `Z` | 回退最近一个可回退活动（服务端校验权限与冲突） |
| `K` | 打开配置界面 |

按键可在原版"按键绑定"中修改。回退需要权限：回退**自己**的活动默认允许；回退**他人**活动需要配置项 `rollbackPermissionLevel`（默认 2，即 OP）。

## 4. 工作原理

### 4.1 活动与连锁反应分离

- 活动：`ActivityRecord`（类型、维度、起止刻、关键帧轨迹、统计计数、状态）。
- 连锁反应：`ConsequenceRecord`（类型、目标、`before` / `after` 负载、因果类型、父连锁反应、刻）。
- 两者**分文件存储**，仅通过 `activityId` 关联；连锁反应不会显示为独立活动。

### 4.2 合并与压缩

`ActivitySession` 负责"一个连续动作 = 一个活动"：
- `MOVE` 在 `movementMergeGapTicks`（默认 40 刻）内持续合并，转向只是新增关键帧；
- `BREAK_BLOCK` / `PLACE_BLOCK` / `ATTACK` / `MOVE_ITEM` / `CRAFT` 在各自合并窗口内合并；
- 空闲超过窗口 → `seal` 落盘；
- 轨迹在活动内按检查点做 RDP 简化，状态变化（疾跑/潜行/落地）强制保留。

### 4.3 因果追踪

- 每个活动持有一个"因果窗口"（活动接触过的坐标 → 对应连锁反应）。
- `Level#setBlock` 的变更在窗口内且距被接触坐标 ≤ 2 格时，归入该活动（同坐标 → `DIRECT`，相邻 → `INDIRECT`）。
- 窗口外、或与任何活动坐标无关的变更**不会被归因**，也不参与回退（符合"不得擅自归属"的要求）。
- 延迟事件（红石/计划刻/流体）落在窗口内即被记录为 `INDIRECT`/`DELAYED`；超出窗口的变化不会被回退，回退时由冲突检测兜底。

### 4.4 回退安全性

`RollbackEngine`（纯逻辑，可单测）：
1. 按 `tick, id` 反序排列连锁反应；
2. **先整体预检**：任一目标状态与记录的 `after` 不符 → 立即中止，一个方块/格子都不改；
3. 逐条应用逆操作；中途失败 → 把已应用的步骤**正向重放**，恢复到回退前状态；
4. `UNATTRIBUTED` 的连锁反应永不回退；
5. 成功/失败都会落盘状态（`ROLLED_BACK` / `NOT_ROLLBACKABLE` + 原因）。

`ServerRestorer` 负责实际写入：方块状态、方块实体 NBT、容器槽位、背包槽位、掉落物实体、实体血量。

### 4.5 存储格式

- 分片文件：`seg-000001.ctz`，头部 `MAGIC + 版本 + 创建时间`。
- 记录帧：`长度(4) + CRC32C(4) + 类型(1) + 负载`；负载字段全部变长编码。
- 记录类型：`ACTIVITY_BEGIN` / `ACTIVITY_CHECKPOINT` / `ACTIVITY_END` / `ACTIVITY_STATUS` / `CONSEQUENCE` / `CONSEQUENCE_STATUS` / `ACTIVITY_DELETE`。
- 崩溃恢复：读取到不完整帧 / 校验失败 / 未知类型即停止并把文件截断到最后一条完整记录；未 `seal` 的活动标记 `INCOMPLETE`（不可回退）。
- 容量控制：超过 `maxActivities` / `maxStorageMegabytes` 时按最旧分片整体删除。
- 同一活动内对同一目标的多次变化会**合并**为一条 `before/after`（例如一个箱子点击 20 次只存一条）。

## 5. 兼容性与明确边界

完整支持（已实现且逻辑可验证）：

- 原版方块状态与方块实体（箱子、熔炉、告示牌等）NBT 的保存与恢复；
- 容器/背包槽位内容（含耐久、附魔、自定义名称等数据组件）；
- 掉落物实体的生成与回收；
- 生物血量；
- 玩家背包槽位（含工具耐久，回退即恢复耐久）。

明确不支持 / 只能部分处理（**不会**宣称可完整回退）：

| 场景 | 处理方式 |
|---|---|
| 其他 Mod 的自定义方块实体 / 自定义数据组件 | 只能恢复序列化得到的部分；无法序列化则活动标记不可回退 |
| 已销毁且无法按 UUID 定位的实体 | 跳过并记录原因 |
| 回退窗口之后世界被他人修改 | 冲突检测中止（不覆盖无关变更） |
| 超出因果窗口的红石/流体连锁 | 不归因、不回退（保守策略） |
| 玩家死亡、受伤、着火、怪物 AI、吸引仇恨等"非玩家主动活动" | 不记录为活动；只在有可靠因果链时才作为连锁反应 |
| 已清理（容量/保留期）的历史 | 显示 `pruned`，不可回退 |

## 6. 构建

```bash
# 需要 JDK 25
./gradlew build
```

产物：`build/libs/ctrlz-1.0.0.jar`。

单元测试（不依赖游戏客户端）：

```bash
./gradlew test
```

覆盖：轨迹压缩、活动记录编解码、存储持久化/崩溃截断/容量清理、回退引擎的顺序/冲突中止/失败回滚。

## 7. 验证状态（重要）

本仓库在交付环境内完成的验证：

- ✅ `gradle build`（Gradle 9.8.2 / JDK 25 / Loom 1.19.4）成功产出 `build/libs/ctrlz-1.0.0.jar`；
- ✅ 16 个核心逻辑单元测试全部通过（轨迹压缩、活动编解码、存储持久化/崩溃截断/容量清理、回退事务）；
- ⚠️ 交付环境无法访问 `services.gradle.org` / `github.com`，因此 `gradlew` 首次运行（需要下载 Gradle 发行包）未能在此环境完成自举；`gradle-wrapper.properties` 指向官方发行包，在正常网络下可直接使用。本次构建使用同版本 Gradle 9.8.2 二进制验证，构建脚本与 wrapper 完全一致。
- ⚠️ **未在真实客户端/服务端进行长时间游戏内实测**（交付环境无图形界面）。首次上机建议按下面清单验证：
  1. 走 200 格后 `G` 查看是否只有一个 `MOVE` 活动、关键帧数远小于 tick 数；
  2. 挖一个箱子 → 回退：方块、箱内物品、掉落物、镐子耐久是否全部恢复；
  3. 打开箱子移动物品后回退，检查容器与背包是否回到原状且无复制；
  4. 制造红石延迟（按钮→活塞）后回退，确认延迟变化是否被归因；
  5. 两人同时修改同一箱子后回退，确认提示"状态冲突"且世界未被改动；
  6. `/stop` 强杀服务端 → 重启，检查历史是否仍在、未完成活动是否为 `incomplete`。
